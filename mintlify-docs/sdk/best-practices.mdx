The SDK verifies what the maker sends. Everything around it is your app's job: storage, scheduling, and the wallet. These are the rules that keep funds recoverable.

## Keys

- **Never reuse a swap index.** Keep a persisted, monotonically increasing counter and increment it before each swap.
- **Store the swap mnemonic,** not the wallet mnemonic, for day-to-day swap operations. Derive it once with `fromWalletMnemonic` and reload it with `fromSwapMnemonic`.
- **Chain swaps use two indexes,** one for the claim key and one for the refund key.

## Persistence

Persist before every step that moves money:

| Before | Persist |
|---|---|
| Funding a lockup or paying an invoice | Swap ID, index, maker URL, the full create response (with `swapAuth`) |
| Broadcasting a claim or refund | Swap ID, action, path, transaction hex, txid, chain, network |
| Sending a pay-through create | The request, the idempotency key, the maker URL |

- Serialize TypeScript responses with `toJson`. `JSON.stringify` throws on `bigint`, and it would throw at the exact step whose purpose is not losing data.
- Treat `swapAuth`, idempotency keys, and swap secrets as secrets. Log `swap.id`, never the whole response.
- After a lost broadcast response, rebroadcast the saved bytes. Never re-sign.
- Serialize concurrent operations on the same swap.

## Verification

- **Create** with the card's `pairHash` so the maker is held to the terms you displayed.
- **Rebuild the `SwapScript`** from the response with your own key before funding or paying. It fails if the lockup is not spendable by you.
- **Check the chain yourself.** The maker's status is information, not proof. Claim against a lockup your own backend has confirmed; refund against a tip height your own backend reports.
- **Check invoices you pay.** For Arkade receives, confirm the hold invoice pays your hash for exactly the quoted amount.

## Fees

- Pass an explicit `feeSatPerVb` or `feeAbsoluteSat` for every spend, and set `feeLimits` as a ceiling.
- Take estimates from Esplora on the same chain as the spend (`@kaleidorg/swap-sdk/chain-data`), not from the maker's fee endpoint.
- If no estimate is available, postpone or apply an explicit policy. Do not substitute a silent default.
- For RGB reverse swaps, compare the quoted `claimFeeRate` with current fees and the remaining timeout before paying.

## Networks

- Keep the network, the maker URL, and the chain endpoints on the same row of [Networks](/sdk/networks). The signet maker settles on Mutinynet, and testnet3 endpoints fail silently against it.
- Validate payout addresses for the right network before paying an invoice. The claim is the first step that would reject a bad address.

## Deadlines and scheduling

The SDK runs no timers. Your app decides when to check:

- On app start and on resume: restore, then reconcile every open swap.
- On a schedule while swaps are open: call the reconciliation helpers (or `venue.reconcile()` for Arkade).
- Leave a margin before claim deadlines: by default 6 blocks on Bitcoin, 60 on Liquid.

## Mobile apps

A swap has a deadline and a phone does not stay awake.

- **Restore on launch.** `masterXpub()` plus `swapRestore()` returns every swap the maker has seen for your wallet, including those still owed a claim or refund.
- **Persist `swapAuth`.** Restore does not return it.
- **Do not trust a backgrounded socket.** The status WebSocket does not survive backgrounding and a dead socket reports no error. Check `isConnected()` on resume and fall back to `swap(id)`.

## Credentials

- Use an [organization key](/sdk/partner-attribution) in client-side code. Keep organization API keys on servers.
- Scrub API keys from error reporters that capture local variables.
