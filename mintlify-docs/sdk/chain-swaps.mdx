Your user has funds on one chain and wants them on another, for example BTC on Bitcoin to L-USDT on Liquid. This is a **chain swap**. `chainPairs()` lists the routes on offer.

## How it works

Your app creates a secret and locks funds on the source chain. The maker locks on the destination chain, to the same secret. Your app claims the maker's lockup, which reveals the secret and lets the maker claim yours. If the maker never locks, your app refunds its own lockup.

A chain swap uses two keys: a refund key for your lockup and a claim key for the maker's.

## Swap

<Steps>
  <Step title="Create the swap">
    ```typescript
    const refundIndex = await nextSwapIndex();
    const claimIndex = await nextSwapIndex();
    const refundKey = master.deriveSwapKey(refundIndex);
    const claimKey = master.deriveSwapKey(claimIndex);
    const preimage = master.derivePreimage(claimIndex);

    const card = (await client.chainPairs())?.BTC?.["L-USDT"];
    if (!card) throw new Error("Route not offered right now");

    const swap = await client.createChainSwap(network, {
      from: "BTC",
      to: "L-USDT",
      preimageHash: preimage.sha256,
      claimPublicKey: claimKey.publicKey,
      refundPublicKey: refundKey.publicKey,
      userLockAmount: 100_000n,
      pairHash: card.hash,
    });

    await store.put(swap.id, toJson({ refundIndex, claimIndex, makerUrl, swap }));
    ```

    The response has `lockupDetails` (where you lock) and `claimDetails` (where the maker locks for you). The SDK checks both against your keys.
  </Step>

  <Step title="Lock">
    Send exactly the expected amount to `swap.lockupDetails.lockupAddress` in one transaction.
  </Step>

  <Step title="Wait for the maker's lockup">
    The swap reaches `transaction.server.mempool`, then `transaction.server.confirmed`.
  </Step>

  <Step title="Claim the L-USDT">
    L-USDT pays its Liquid fee in L-BTC, so the claim is a **caller-funded PSET**: the SDK prepares a partial transaction, your Liquid wallet adds an L-BTC input for the fee and signs it, and the SDK finalizes it with your secret.

    ```typescript
    // Both sides rebuild from the response; a mismatch throws here.
    const lockupScript = SwapScript.fromChain("bitcoin", network, "lockup", swap.lockupDetails, refundKey.publicKey);
    const claimScript = SwapScript.fromChain("liquid", network, "claim", swap.claimDetails, claimKey.publicKey);

    const prepared = await claimScript.prepareLiquidClaim({
      outputAddress: myExplicitLiquidAddress, // an unconfidential Liquid address
      swapId: swap.id,
      maxFee: 1_000n,                         // your fee ceiling, in L-BTC sats
      quotedFeeCap: 1_000n,                   // the claim fee the pair card quoted; the lower cap wins
      makerBaseUrl: makerUrl,
      network,
      liquidEsploraUrl,
    });

    // Your Liquid wallet funds the fee with L-BTC, blinds, and signs its own input.
    const funded = await myLiquidWallet.fundAndSign(prepared.template());

    const claim = prepared.finalizeClaim(funded, claimKey.secretKey, preimage.preimage);
    // Save claim.hex() first, then:
    await claim.broadcast(network, undefined, liquidEsploraUrl);
    ```

    `myLiquidWallet.fundAndSign` stands for your wallet's code: it takes the template's `pset`, adds and signs an L-BTC input that covers the fee, and returns `{ pset, paymentOutputSecrets }`. The swap ends in `transaction.claimed`.

    For a chain swap that pays out L-BTC or BTC instead, claim with `claimScript.constructCooperativeClaim(preimage, params, lockupScript, refundKey.secretKey)`, which signs with your **refund** key against the lockup script, and fall back to `constructClaim(preimage, { ...params, cooperative: false })` if the maker does not cooperate.
  </Step>
</Steps>

## Accept a re-quote

If you locked a different amount than quoted, the maker can offer a new destination amount. Accepting it needs the swap's `swapAuth`:

```typescript
const quote = await client.quote(swap.id);
await client.acceptQuote(swap.id, quote.amount, swap.swapAuth);
```

Without `swapAuth` the call fails with `401 invalid_swap_auth`, and the swap expires into its refund.

## If something goes wrong

Refund your lockup with `lockupScript.constructRefund({ ...params, swapAuth: swap.swapAuth })`, or let `refundChainSwap` choose between the cooperative and script paths. Your refund uses the **source** chain's deadline; your claim uses the **destination** chain's.

<Note>
USDT-RGB is not a chain-swap asset. For BTC ↔ USDT-RGB on chain, use an [atomic swap](/sdk/rgb-swaps#atomic-swaps-on-l1).
</Note>
