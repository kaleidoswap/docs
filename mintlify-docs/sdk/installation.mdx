All four packages share one version number. Install the one for your runtime.

<CodeGroup>
```bash TypeScript
npm install @kaleidorg/swap-sdk
```

```bash Python
python -m pip install kaleidorg_swap_sdk
```

```bash React Native
npm install @kaleidorg/swap-sdk-react-native
```

```toml Rust (Cargo.toml)
[dependencies]
kaleidorg-swap-sdk = { git = "https://github.com/kaleidoswap/swap-sdk", tag = "vX.Y.Z" }
```
</CodeGroup>

The current release is <code>v{swapSdkVersion}</code>. Use that tag for the Rust crate.

## Supported runtimes

| Package | Runtime |
|---|---|
| `@kaleidorg/swap-sdk` | Browsers and Node 22+ |
| `kaleidorg_swap_sdk` | Python 3.10+. Wheels for Linux x86_64/aarch64, macOS x86_64/arm64, Windows x86_64; other platforms build the source distribution and need Rust 1.88+ |
| `@kaleidorg/swap-sdk-react-native` | iOS and Android, new architecture, bare or prebuilt apps (not Expo Go) |
| `kaleidorg-swap-sdk` (Rust) | Rust 1.88+, native and `wasm32-unknown-unknown`. Not published to crates.io; depend on a tag |

## TypeScript: load the WebAssembly binary

The TypeScript package wraps the Rust engine compiled to WebAssembly. Call `init()` once before you construct any client. It takes no argument in browsers or in Node.

```typescript
import { init, SwapClient } from "@kaleidorg/swap-sdk";

await init();
const client = SwapClient.forNetwork("signet");
```

Your bundler must emit the packaged `vendor/bindings_wasm_bg.wasm` asset. To serve the binary from your own CDN, pass its location:

```typescript
await init(new URL("/assets/bindings_wasm_bg.wasm", location.origin));
```

`wasmUrl` points at the packaged binary if you need to copy it. For a pre-compiled `WebAssembly.Module`, use `initWithModule`.

<Warning>
Bundling the Node entry into a single file (a CLI or serverless artifact) moves the module away from its packaged `vendor/` folder, and the default lookup finds nothing. Copy `bindings_wasm_bg.wasm` next to your output and pass it to `init()`. This only fails at runtime, so check it before you ship.
</Warning>

### Subpath entry points

| Import | What it is | Needs `init()` |
|---|---|---|
| `@kaleidorg/swap-sdk` | The full swap surface | Yes |
| `@kaleidorg/swap-sdk/pay-through` | HTTP client for [pay-through](/sdk/pay-through) | No |
| `@kaleidorg/swap-sdk/chain-data` | Esplora fee and tip-height helpers | No |
| `@kaleidorg/swap-sdk/arkade` | The [Arkade Intents venue](/sdk/arkade) (peer-depends on `@arkade-os/sdk` and `@arkade-os/swap`) | No |

## React Native

The browser package cannot run on a device because Hermes has no WebAssembly. `@kaleidorg/swap-sdk-react-native` is the same Rust engine compiled for iOS and Android and exposed as a turbo module.

- Prebuilt native binaries are downloaded from the release on install and verified against a SHA-256 manifest shipped in the npm package. No Rust toolchain, NDK, or Xcode is needed. Run `pod install` for iOS afterwards.
- With pnpm 10 or later, allow the package's install script, or the binaries are never fetched and the module is missing at first import:

  ```yaml pnpm-workspace.yaml
  onlyBuiltDependencies:
    - "@kaleidorg/swap-sdk-react-native"
  ```

- With Expo, use `expo prebuild` and a development build.
- The Arkade venue is a separate entry, `@kaleidorg/swap-sdk-react-native/arkade`. It needs `@kaleidorg/swap-sdk`, `@arkade-os/sdk`, and `@arkade-os/swap` installed alongside, and Metro must resolve package `exports` (the default from React Native 0.79).

Phones sleep and swaps have deadlines. Read the mobile notes in [Best practices](/sdk/best-practices#mobile-apps) before you ship.

## Pinning a version

The SDK is `0.x`: a minor release can change the public surface, and patch releases never do. Depend on the minor you tested and take its patches: <code>"@kaleidorg/swap-sdk": "^{swapSdkVersion}"</code> in `package.json`, or <code>kaleidorg_swap_sdk~={swapSdkVersion}</code> in Python. On a `0.x` version both forms accept patches and never cross into the next minor.

Read the [changelog](/sdk/changelog) before moving to a new minor. Breaking changes are listed at the top of each release entry.
