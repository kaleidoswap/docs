Names are shown as TypeScript / Python. Rust uses the Python spelling on `BoltzApiClientV2` and `SwapScript`. React Native exposes the same surface as Python with camelCase names, generated from the same bindings. The published TypeScript declarations (`dist/index.d.ts`) document every type in full.

## `SwapClient`

The maker API client. In TypeScript it comes from `SwapClient.forNetwork`, `new SwapClient(baseUrl, timeoutSecs?)`, `createKaleidoOrgClient`, or `createKaleidoMakerClient`. In Python: `SwapClient.default(network)`, `SwapClient(base_url, timeout)`, `SwapClient.kaleido_org(...)`, or `SwapClient.kaleido_maker(...)`.

## `SwapScript`

The swap script rebuilt on your side, and the claim and refund builder.

| Method | What it does |
|---|---|
| `fromSubmarine(chain, network, response, ourPubkey)` | Rebuild from a submarine create response |
| `fromReverse(chain, network, response, ourPubkey)` | Rebuild from a reverse create response |
| `fromChain(chain, network, side, details, ourPubkey)` | Rebuild one side (`"lockup"` or `"claim"`) of a chain swap |
| `fromRestored(entry, ourPubkey, network, side?)` | Rebuild from a restore entry |
| `constructClaim(preimage, params)` | Claim (cooperative by default) |
| `constructCooperativeClaim(preimage, params, lockupScript, refundKeySecret)` | Cooperative chain-swap claim |
| `constructRefund(params)` | Refund (cooperative by default) |
| `prepareLiquidClaim(...)` / `prepareLiquidRefund(...)` | Caller-funded PSET for L-USDT |
| `prepareRgbClaim(...)` / `prepareRgbRefund(...)` | PSBT for an rgb-lib wallet to color |
| `prepareRgbCooperativeRefund(...)` | Early co-signed RGB submarine refund |

`chain` is `"bitcoin"` or `"liquid"`. Python uses snake_case and takes a `SwapTransactionParams` with a `Fee.RELATIVE(sat_per_vb)` or `Fee.ABSOLUTE(sats)`.

## Numbers in TypeScript

- Parameters declared `bigint` need a `BigInt` (`0n`); a plain number throws a `TypeError` before the SDK can attach a code.
- 64-bit fields inside request objects accept `bigint | number`. Unsafe numbers above `Number.MAX_SAFE_INTEGER` are rejected before the request is sent.
- 64-bit response fields are always `bigint`, including amounts, timestamps, and the restore index. 32-bit fields (key indexes, output indexes, reverse and chain timeout heights) stay `number`.
- Serialize responses with `toJson`, not `JSON.stringify`.
