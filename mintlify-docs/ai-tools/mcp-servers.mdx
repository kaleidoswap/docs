KaleidoSwap exposes its wallet, DEX, and payment functionality to AI agents (Claude Desktop, [KaleidoAgent](/ai-tools/kaleido-agent), [KaleidoMind](/ai-tools/kaleido-mind)-based hosts, or any other [MCP](https://modelcontextprotocol.io) client) through **`kaleido-mcp`**, the unified server recommended for new integrations. It supersedes the earlier standalone wallet servers; see the migration notes at the end of this page.

## What you need

| Operation | Prerequisite |
|---|---|
| Market reads and quotes | MCP client and Node.js; no seed or local node |
| RGB wallet and atomic RGB swaps | Reachable, unlocked RGB Lightning Node |
| Spark or Liquid wallet | Optional wallet package and its mnemonic |
| Submarine swaps | Optional swap SDK, Node.js 22+, and a configured funding wallet |

The model calls tools through your MCP client. Starting the server in a terminal
only waits for protocol requests; it does not open a chat.

## Installation & Configuration

`kaleido-mcp` is published to npm, which is the quickest way to a first tool call. Start on signet:

```bash
KALEIDO_NETWORK=signet npx -y kaleido-mcp
```

<Note>
  This page documents `kaleido-mcp` 0.3.0 and later. 0.3.0 adds the `KALEIDO_NETWORK`
  preset and the `kaleido_node_*` lifecycle tools, and drops the order-based swap
  tools in favour of atomic swaps. If `npx` resolves an older cached version, run
  `npx -y kaleido-mcp@latest` once, or build from source.
</Note>

<Note>
  From 0.3.1 the Spark and Liquid wallets are optional peer dependencies that plain
  `npx -y kaleido-mcp` does not install. With `WDK_SEED` or `LIQUID_MNEMONIC` set but
  the package missing, the server still starts and logs an install hint. To enable them:

  ```bash
  npx -y -p kaleido-mcp -p @tetherto/wdk-wallet-spark -p @kaleidorg/wdk-wallet-liquid kaleido-mcp
  ```
</Note>

In practice an MCP host runs this for you, point its config at the command (see [Client Configuration](#client-configuration) below). For development, or to run a specific commit, build from source instead:

```bash
git clone https://github.com/kaleidoswap/kaleido-mcp
cd kaleido-mcp
npm install
npm run build
```

Either way, the server reads the same environment variables and speaks stdio by default:

```bash
# stdio (Claude Desktop, Claude Code, KaleidoAgent, ...)
KALEIDO_NETWORK=signet WDK_SEED="word1 word2 ..." node dist/index.js

# HTTP transport
PORT=3010 KALEIDO_NETWORK=signet WDK_SEED="word1 word2 ..." node dist/index.js
```

### Network Preset

`KALEIDO_NETWORK` picks a set of defaults in one variable. It accepts `signet` (the default from 0.3.1) or `mainnet`:

| Preset | KaleidoSwap API | Spark network |
|--------|-----------------|---------------|
| `signet` | `https://api.signet.kaleidoswap.com` | Spark's test network (`REGTEST` in the Spark SDK) |
| `mainnet` | None: set `KALEIDOSWAP_API_URL` to your own maker endpoint | `MAINNET` |

The preset only fills in defaults. Any variable you set explicitly, such as `KALEIDOSWAP_API_URL` or `SPARK_NETWORK`, wins over it. There is no public mainnet KaleidoSwap API, so `mainnet` without `KALEIDOSWAP_API_URL` stops the server at startup, as does an unknown value. `RLN_NODE_URL` is not part of the preset: point it at your own node, which on signet is usually the one [KaleidoCLI](/cli/installation) runs on `http://localhost:3001`.

| Env var | Required | Description |
|---------|----------|--------------|
| `KALEIDO_NETWORK` | No | `signet` (default) or `mainnet`. Sets the defaults in [Network Preset](#network-preset) |
| `WDK_SEED` | Yes, for Spark tools | BIP-39 mnemonic for the Spark wallet. Also needs the optional `@tetherto/wdk-wallet-spark` package. The server still boots without either, the Spark tools are just disabled |
| `LIQUID_MNEMONIC` | Yes, for Liquid tools | BIP-39 mnemonic for the Liquid wallet. Also needs the optional `@kaleidorg/wdk-wallet-liquid` package |
| `SPARK_NETWORK` | No | Overrides the preset's Spark network: `MAINNET`, or `REGTEST` for Spark's test network |
| `SPARK_SCAN_API_KEY` | No | SparkScan API key |
| `SPARK_USDT_TOKEN` | No | Default Spark token identifier |
| `RLN_NODE_URL` | No | RLN daemon URL, default `http://localhost:3001` |
| `KALEIDOSWAP_API_URL` | With `mainnet` | KaleidoSwap maker API URL, overriding the preset. Required on `mainnet`, which has no public endpoint. `KALEIDO_API_URL` is accepted as well |
| `KALEIDO_BIN` | No | Path to the `kaleido` binary, for the node lifecycle tools |
| `KALEIDO_NODE_URL` | No | Node URL passed as `--node-url` to the node lifecycle tools |
| `KALEIDO_API_URL` | No | API URL passed as `--api-url` to the node lifecycle tools, and a fallback for `KALEIDOSWAP_API_URL` |
| `KALEIDO_ENV_NAME` | No | Default environment name for the node lifecycle tools |
| `PORT` | No | Enable Streamable HTTP transport instead of stdio |
| `MCP_AUTH_TOKEN` | No | Bearer token for HTTP mode |

### Runtime Compatibility

Check the installed package versions when diagnosing an integration. QVAC-backed
Mind hosts require `@qvac/sdk >=0.20.0`. The `kaleidoswap_submarine_*` tools also
need the optional `@kaleidorg/swap-sdk` package and Node.js 22 or newer.
A tool appearing in the catalog does not guarantee that its wallet, node or
optional dependency is configured. A successful `/health` response only confirms
that the HTTP process is running.

The [generated MCP reference](https://github.com/kaleidoswap/kaleido-mcp/blob/main/docs/TOOLS.md)
lists the current schemas. Use the reference at your installed release tag when
building a version-pinned integration.

### Legacy Aliases

Some tools are still reachable under older names (`rln_*` for `wdk_*`, generic `get_*` for the `l402_get_*` market tools) for backward compatibility with earlier integrations. New integrations should use the canonical `wdk_*` / `l402_*` names.

## Tool Surface by Domain

All tools below are served by `kaleido-mcp` over a single connection. The 🔒 icon marks spend-moving tools in these docs; `kaleido-mcp` does not encode a confirmation flag, so whether a call is confirmed before executing is the MCP host's behavior. The exception is the WDK built-in `sendTransaction` and `transfer`, which request an MCP-elicitation confirmation themselves before broadcasting.

## Client Configuration

Add the unified server to your MCP client. Start with market reads and add wallet packages only when you need them.

<Warning>
  The starter configuration below needs no mnemonic. If you later add wallet seeds, keep that configuration private and out of version control.
</Warning>

<CodeGroup>
```json Claude Desktop
{
  "mcpServers": {
    "kaleido": {
      "command": "npx",
      "args": ["-y", "kaleido-mcp"],
      "env": {
        "KALEIDO_NETWORK": "signet",
        "RLN_NODE_URL": "http://localhost:3001"
      }
    }
  }
}
```

```bash Claude Code
claude mcp add kaleido \
  --env KALEIDO_NETWORK=signet \
  --env RLN_NODE_URL=http://localhost:3001 \
  -- npx -y kaleido-mcp
```
</CodeGroup>

On Claude Desktop the file is `claude_desktop_config.json` (**Settings > Developer > Edit Config**). `WDK_SEED` and the `@tetherto/wdk-wallet-spark` package are optional: leave them out and the Spark tools are disabled while the RGB node, DEX, payment and market tools keep working. `REGTEST` is the name the Spark SDK gives its hosted test network.

## First Run

Start with market reads, then wallet reads, then a quote. Reading balances and requesting a quote do not move funds; payment and execution tools do.

<Steps>
  <Step title="Add the gateway to your host">
    Drop the `kaleido-mcp` block into your MCP host's config with `KALEIDO_NETWORK` set to `signet`. The full JSON is in [Client Configuration](#client-configuration) above.
  </Step>

  <Step title="Restart the host">
    MCP hosts read their config at startup. A running client will not pick up a new server until you restart it.
  </Step>

  <Step title="Call a read-only tool">
    Start with something that cannot move funds. Ask for market data, which needs no seed and no node:

    ```
    What is the current Bitcoin price and the Fear and Greed index?
    ```

    That exercises `l402_get_price` and `l402_get_sentiment`. Check that the client reports successful tool calls; a model-generated answer alone does not verify the connection.
  </Step>

  <Step title="Check the wallet is wired">
    After enabling the optional Spark package and seed, confirm the wallet tools resolve:

    ```
    Show me my Spark balance and my Spark address.
    ```

    This calls `spark_get_balance` and `spark_get_address`. If discovery succeeded but this call fails, check the optional wallet package, seed, network and the tool error.
  </Step>

  <Step title="Quote before you trade">
    Ask for a price without placing anything:

    ```
    Quote 100000 sats of BTC into USDT. Do not execute anything.
    ```

    `kaleidoswap_get_quote` returns an `rfq_id`, raw amounts, the fee, and an expiry. Read the raw amounts carefully: they are in the asset's smallest unit, not display units.
  </Step>

  <Step title="Execute only once the quote looks right">
    An atomic swap needs the DEX tools and the wallet tools together, and the node must hold the asset in a channel. The [cross-server sequence](#atomic-swap-across-servers) below shows each call in order.
  </Step>
</Steps>

<Warning>
  A generic MCP host is the least protected path. `kaleido-mcp` does not encode a confirmation flag, so if your client auto-approves tool calls, an LLM can spend from the configured wallet without asking you. Use a test network seed until you know how your client handles approvals.
</Warning>

## Atomic Swap Flow {#atomic-swap-across-servers}

An atomic swap needs the DEX tools and the wallet tools together. `kaleido-mcp` speaks to the maker via its `kaleidoswap_*` tools and drives the taker node via its `wdk_*` tools. Nothing is custodied at any step, and the HTLC settles on Lightning.

```
kaleidoswap_get_quote        → rfq_id + raw amounts
kaleidoswap_atomic_init      → swapstring + payment_hash
wdk_atomic_taker             → whitelist the HTLC on the node
wdk_get_node_info            → taker_pubkey
kaleidoswap_atomic_execute   → trigger HTLC settlement
kaleidoswap_atomic_status    → poll until Succeeded
```

Every step above runs through the same `kaleido-mcp` connection, since both prefixes are available at once.

## Paid API Access

The Machine Payments Protocol flow lets an agent buy access to a gated resource without an API key or a signup, paying the invoice over Lightning.

```
mpp_request_challenge(url)          → challenge { invoice, challenge_id }
wdk_mpp_pay(invoice, challenge_id)  → payment credential
mpp_submit_credential(url, cred)    → { ok, data, receipt }
```


## Retired Servers

These names are migration references, not additional servers to install:

| Older entry point | Current path |
|---|---|
| `wdk-wallet-mcp` | `wdk_*` in `kaleido-mcp` |
| `wdk-wallet-spark-mcp` | `spark_*` plus the optional Spark package; use `WDK_SEED` instead of `WDK_SPARK_SEED` |
| `wdk-wallet-liquid-mcp` | `liquid_*` plus the optional Liquid package |
| `kaleidoswap-mcp` | `kaleidoswap_*`; use atomic swaps instead of the removed REST order flow |
| `l402-gateway-mcp` | `mpp_*` / `l402_*` |
| `kaleido-node-mcp` | `kaleido_node_*` for lifecycle operations; `wdk_*` for the wallet |

Keep existing `rln_*` aliases where required by your host. For new raw MCP
integrations prefer canonical names and check the generated schemas for your
installed version before migrating arguments.
