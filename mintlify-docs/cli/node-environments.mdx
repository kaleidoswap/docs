## Named Environment Model

`kaleido node` manages **named Docker Compose environments** stored under a base directory, which defaults to:

```text
~/.kaleido
```

Each environment gets its own compose file and volumes, which makes it practical to keep separate local stacks for development, testing, or demos.

Example layout:

```text
~/.kaleido/
├── config.json
├── default/
│   ├── docker-compose.yml
│   └── volumes/
│       └── dataldk0/
└── testenv/
    ├── docker-compose.yml
    └── volumes/
        ├── dataldk0/
        └── dataldk1/
```

Each node in an environment is a `rgb_node_<n>` service with its own data volume. Only the node itself runs locally: bitcoind, the indexer, and the RGB proxy are remote services.

## Create An Environment

```bash
kaleido node create
kaleido node create testenv
```

The wizard prompts for:

1. Base directory
2. Environment name
3. Node count
4. Bitcoin network
5. Base daemon and peer ports
6. Whether to start the environment immediately

## Lifecycle Commands

| Command | Purpose |
|--------|---------|
| `kaleido node list` | Show all environments and their node URLs |
| `kaleido node use <name> [--node N]` | Point the active `node-url` at one node in an environment |
| `kaleido node up <name>` | Start containers |
| `kaleido node stop <name>` | Stop containers without deleting data |
| `kaleido node down <name>` | Stop and remove containers and networks |
| `kaleido node ps <name>` | Show container status |
| `kaleido node logs <name>` | Stream logs |
| `kaleido node clean <name>` | Delete environment data volumes |

When exactly one environment exists, commands like `up`, `stop`, `logs`, and `clean` can auto-detect it.

## Switch The Active Node

Use `kaleido node use` to update the configured node URL:

```bash
kaleido node use default
kaleido node use testenv --node 2
```

Node 1 listens on daemon port 3001 and peer port 9735, node 2 on 3002 and 9736, and so on from the base ports chosen at creation. `kaleido node list` marks the active node with `●`.

This is the bridge between Docker-managed environments and all node-dependent commands such as `wallet`, `asset`, `channel`, and `payment`.

## Initialize And Unlock

After a fresh environment starts, initialize the wallet once:

```bash
kaleido node init
```

Key options:

- `--password` to pass the wallet password directly
- `--mnemonic` to restore from an existing mnemonic during initialization

After every restart, unlock the wallet:

```bash
kaleido node unlock
```

Unlock is also where the node learns which Bitcoin services to use. Run interactively, it offers a service profile — signet defaults, regtest defaults, or custom — and then asks how the node should follow the chain.

### Chain sync mode

| Mode | Behaviour |
|------|-----------|
| `--chain-sync block` (default) | Reads blocks from a bitcoind over RPC |
| `--chain-sync transaction` | Follows the chain from the indexer alone, with no bitcoind |

With `transaction`, every `--bitcoind-*` option is ignored:

```bash
kaleido node unlock --chain-sync transaction --indexer-url https://esplora.signet.kaleidoswap.com
```

### Unlock options

| Option | Purpose |
|--------|---------|
| `--password`, `-p` | Wallet password, prompted securely if omitted |
| `--chain-sync` | `block` or `transaction`, as above |
| `--bitcoind-user`, `--bitcoind-pass` | bitcoind RPC credentials |
| `--bitcoind-host`, `--bitcoind-port` | bitcoind RPC endpoint |
| `--indexer-url` | Esplora (`https://…`) or Electrum (`host:port`) |
| `--proxy-endpoint` | RGB proxy endpoint |
| `--announce-alias` | Lightning peer alias to announce |
| `--announce-address` | Public address for peer discovery, repeatable |

By default the command uses the KaleidoSwap signet services. For a scripted unlock, pass the password explicitly and disable prompts:

```bash
kaleido --agent node unlock --password <password>
```

## Inspect And Lock

```bash
kaleido node info
kaleido node lock
```

Use `info` to confirm the node is reachable and correctly configured before running wallet, channel, or swap flows.

## Node Swap Operations

The nested `swap` group supports atomic and low-level swap operations on the node side:

```bash
kaleido node swap pubkey
kaleido node swap whitelist --swapstring '30/rgb:abc.../10/rgb:def.../...'
```

## Recommended Local Flow

```bash
kaleido node create devnet
kaleido node up devnet
kaleido node use devnet
kaleido node init
kaleido node unlock
kaleido node info
```

## Operational Notes

- `clean` is irreversible because it removes the underlying data volumes.
- `down` removes containers and networks, but preserves volumes.
- `logs` accepts `--service` to limit output to one container.

Continue to [Wallet, Assets, And Payments](/cli/wallet-assets-payments) for the commands you run against an unlocked node.
