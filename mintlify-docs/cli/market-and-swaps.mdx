## Market Data

The `market` group is the read-only entry point for pairs, quotes, routes, and maker metadata.

| Command | Purpose |
|--------|---------|
| `kaleido market assets` | List tradeable assets |
| `kaleido market pairs` | List trading pairs |
| `kaleido market quote <pair>` | Request a quote |
| `kaleido market info` | Show maker node information |
| `kaleido market routes <pair>` | List route options |

### Quote examples

```bash
kaleido market quote BTC/USDT --from-amount 0.001
kaleido market quote BTC/USDT --to-amount 500 --from-layer BTC_LN --to-layer RGB_LN
```

Important quote options:

- `--from-amount` or `--to-amount` — exactly one of the two, since a quote is anchored on one side only
- `--from-layer`
- `--to-layer`

<Note>
  **Amounts here are display units.** `--from-amount 0.001` means 0.001 BTC, not 1000 sat. The raw integer amounts described in [Wallet, Assets, And Payments](/cli/wallet-assets-payments) apply to `asset` and `payment` commands, not to quotes and swaps.
</Note>

### Layer values

The accepted set depends on the command:

| Command | Layers |
|---------|--------|
| `market quote` | `BTC_LN`, `RGB_LN`, `BTC_ONCHAIN` |
| `swap atomic init`, `swap atomic run` | `BTC_L1`, `BTC_LN`, `RGB_L1`, `RGB_LN` |

Both options are optional: when omitted, the layers are derived from the requested pair direction.

## Swap Scopes

Swaps are split across two command groups:

| Scope | Use case |
|------|----------|
| `swap atomic` | Run maker-backed atomic swaps using your local node as taker |
| `node swap` | Drive low-level local RLN swap steps directly (under the `node` group) |

## Atomic Swap Flow

Use `swap atomic` when the maker side is remote but execution uses your local node as taker.

### Subcommands

| Command | Purpose |
|--------|---------|
| `kaleido swap atomic init <pair>` | Initialize the atomic swap (`--yes` accepts the quoted price, required non-interactively) |
| `kaleido swap atomic execute` | Execute the initialized swap (`--swapstring`, `--taker-pubkey`, `--payment-hash`, prompted if omitted; `--auto-whitelist`) |
| `kaleido swap atomic status <payment-hash>` | Track atomic swap status |
| `kaleido swap atomic run <pair>` | Run init, whitelist, and execute in one command |

### Example

```bash
kaleido swap atomic run BTC/USDT --to-amount 5
```

You can also provide:

- `--taker-pubkey`
- `--yes`
- explicit `--from-layer` and `--to-layer`

## Local Node Swap Flow

Use `node swap` for low-level RLN swap steps (these live under the `node` command group):

| Command | Purpose |
|--------|---------|
| `kaleido node swap pubkey` | Print the taker public key |
| `kaleido node swap init` | Start a local maker-init swap flow (`--from-asset`, `--qty-from`, `--to-asset`, `--qty-to`, `--timeout`) |
| `kaleido node swap whitelist --swapstring '<swapstring>'` | Whitelist the swap on the taker side |
| `kaleido node swap execute` | Execute after whitelisting |
| `kaleido node swap status <payment-hash>` | Inspect status (`--taker` or `--maker`) |
| `kaleido node swap list` | List swaps known to the node |

This path is useful for debugging, demos, and lower-level protocol operations where you want each step exposed separately.

A swapstring carries six slash-separated fields, and the CLI validates them before whitelisting:

```text
<from_amount>/<from_asset>/<to_amount>/<to_asset>/<expiry>/<payment_hash>
```

Always quote it on the command line so the shell leaves it intact. See [Troubleshooting](/cli/troubleshooting#market-and-swaps) for what the validation errors mean.

## Recommended Trade Flow

### Browse the market (no node required)

```bash
kaleido market pairs
kaleido market quote BTC/USDT --from-amount 0.001
```

Executing a swap requires a local RLN node — use the atomic flow below.

### With a local node

```bash
kaleido node unlock
kaleido node swap pubkey
kaleido swap atomic run BTC/USDT --from-amount 0.001 --from-layer BTC_LN --to-layer RGB_LN
```

Use [Command Reference](/cli/command-reference) for the complete command map.
