Your user pays over Lightning and wants the funds on chain. This is a **reverse swap**.

## How it works

Your app creates a secret and pays a hold invoice locked to it. The maker then locks the funds on chain to the same secret. Your app claims them, which reveals the secret and lets the maker settle your payment.

Until your app claims, the Lightning payment is held, not settled. If the maker never locks, the payment is released back.

## Receive funds

<Steps>
  <Step title="Create the swap">
    ```typescript
    const index = await nextSwapIndex();
    const claimKey = master.deriveSwapKey(index);
    const preimage = master.derivePreimage(index);

    const card = (await client.reversePairs())?.BTC?.["L-BTC"]; // Lightning -> L-BTC
    if (!card) throw new Error("Route not offered right now");

    const swap = await client.createReverseSwap(network, {
      from: "BTC",
      to: "L-BTC",
      invoiceAmount: 50_000n,
      preimageHash: preimage.sha256,
      claimPublicKey: claimKey.publicKey,
      pairHash: card.hash,
    });

    await store.put(swap.id, toJson({ index, makerUrl, swap }));
    ```

    The SDK checks that the invoice is locked to your secret and that the lockup is claimable with your key.
  </Step>

  <Step title="Pay the invoice">
    Pay `swap.invoice` from any Lightning wallet. Check your payout address first: the claim is the first step that would reject a wrong-network address, and by then the invoice is paid.
  </Step>

  <Step title="Wait for the maker's lockup">
    The swap reaches `transaction.mempool`, then `transaction.confirmed`.
  </Step>

  <Step title="Claim">
    ```typescript
    const script = SwapScript.fromReverse("liquid", network, swap, claimKey.publicKey);

    const claim = await script.constructClaim(preimage.preimage, {
      outputAddress: myLiquidAddress,
      swapId: swap.id,
      keysSecretHex: claimKey.secretKey,
      makerBaseUrl: makerUrl,
      network,
      liquidEsploraUrl,
    });
    // Save claim.hex() first, then:
    await claim.broadcast(network, undefined, liquidEsploraUrl);
    ```

    The swap ends in `invoice.settled`.
  </Step>
</Steps>

```python
claim_key = master.derive_swap_key(index)
preimage = master.derive_preimage(index)
btc = sdk.btc_chain_from_network(network)

swap = await client.create_reverse_swap(
    sdk.CreateReverseRequest(
        invoice_amount=50_000, _from=btc, to=lbtc,
        preimage_hash=preimage.sha256(), claim_public_key=claim_key.public(),
    )
)
script = sdk.SwapScript.from_reverse(chain=lbtc, reverse_response=swap, our_pubkey=claim_key.public())
```

## If something goes wrong

- **The maker never locks**, or its lockup fails (`transaction.failed`, `transaction.refunded`): your Lightning payment is released automatically. Nothing to do.
- **Your app was offline:** claim as soon as it comes back. A claim must confirm before the swap's `timeoutBlockHeight`. `claimReverseSwap` checks the remaining margin and your chain evidence before revealing the secret; see [Claims and refunds](/sdk/claims-and-refunds).
- **The broadcast response was lost:** rebroadcast the saved transaction. Never sign a second claim.

## Receiving other assets

| Asset you receive | What changes |
|---|---|
| BTC | `to: "BTC"`, `SwapScript.fromReverse("bitcoin", ...)`, a Bitcoin Esplora URL |
| L-USDT | `to: "L-USDT"`. The claim uses a caller-funded PSET: your wallet adds L-BTC for the fee (`prepareLiquidClaim`) |
| USDT-RGB | Pin the RGB contract, and your rgb-lib wallet colors the claim. See [Swap BTC and USDT on RGB](/sdk/rgb-swaps) |
