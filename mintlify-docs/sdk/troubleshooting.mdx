## Errors

Every rejection that reaches the Rust engine is an `Error` with a stable `code`. Narrow it with `isKaleidoSwapError`:

```typescript TypeScript
import { isKaleidoSwapError } from "@kaleidorg/swap-sdk";

try {
  await client.createReverseSwap("signet", request);
} catch (error) {
  if (isKaleidoSwapError(error)) {
    console.error(error.code, error.message);
  } else {
    throw error;
  }
}
```

- `InvalidArgument`: the binding rejected an input, such as a malformed key or a request missing a field. The message names the field.
- Engine codes, such as `ClaimFallbackFailed` or `rgb_fee_input_required`: the swap engine refused the operation.
- `Internal`: a failure inside the binding.

Values rejected by the generated WebAssembly glue before Rust sees them stay plain JavaScript errors. The common one is a `TypeError` from passing a `number` where a `bigint` is declared.

In Python, errors are raised as `kaleidorg_swap_sdk.Error` variants.

## Installation and loading

<AccordionGroup>
  <Accordion title="init() fails or the WebAssembly binary is not found">
    Your bundler must emit `vendor/bindings_wasm_bg.wasm`. If you bundled the Node entry into a single file, copy the binary next to your output and pass it to `init()`. To serve it yourself, pass its URL: `await init(new URL("/assets/bindings_wasm_bg.wasm", location.origin))`.
  </Accordion>

  <Accordion title="React Native: native module missing at first import">
    With pnpm 10+, add `@kaleidorg/swap-sdk-react-native` to `onlyBuiltDependencies` so its install script fetches the binaries. If the release archive could not be downloaded, reinstall once GitHub is reachable. Expo Go is not supported; use a development build.
  </Accordion>

  <Accordion title="Python: no wheel for my platform">
    Prebuilt wheels cover Linux x86_64/aarch64, macOS x86_64/arm64, and Windows x86_64. Elsewhere pip builds the source distribution, which needs Rust 1.88+.
  </Accordion>
</AccordionGroup>

## Networks

<AccordionGroup>
  <Accordion title="forNetwork('mainnet') throws">
    There is no KaleidoSwap mainnet maker yet. The SDK errors instead of falling back to a third party. Use `signet`, or pass an explicit maker URL.
  </Accordion>

  <Accordion title="The lockup never shows up, or a claim cannot find the output">
    Check that the chain endpoint matches the network. The signet maker settles on Mutinynet (`https://esplora.signet.kaleidoswap.com`); a testnet3 endpoint encodes addresses the same way and fails silently. See [Networks](/sdk/networks).
  </Accordion>
</AccordionGroup>

## Creating swaps

<AccordionGroup>
  <Accordion title="TypeError: Cannot convert 0 to a BigInt">
    A parameter declared `bigint` got a `number`. Use `0n`, or `BigInt(value)`.
  </Accordion>

  <Accordion title="JSON.stringify throws on a response">
    Responses carry `bigint` values. Use `toJson` from the SDK.
  </Accordion>

  <Accordion title="Create fails with a validation error">
    The SDK refused the maker's response because it does not match your request or keys: script, lockup address, timeout, or invoice hash. Do not fund it. Check that you passed the right public key and preimage hash, and that you are talking to the maker you expect.
  </Accordion>

  <Accordion title="Chain swap: 'needs claimPublicKey and refundPublicKey'">
    Chain swaps require both keys so both lockup scripts can be verified. Derive them from two indexes.
  </Accordion>

  <Accordion title="Reverse swap to ARKD is refused">
    Arkade is not a Boltz route. Use `IntentsCorridor` and the Arkade venue. See [Arkade swaps](/sdk/arkade).
  </Accordion>

  <Accordion title="Organization key or API key rejected locally">
    The value is malformed: an organization key must be a valid 64-hex x-only point, and an API key must look like `kld_test_…` or `kld_live_…`. The maker URL must be `https` unless it is a loopback address. A client cannot carry both credentials.
  </Accordion>
</AccordionGroup>

## Claims and refunds

<AccordionGroup>
  <Accordion title="acceptQuote fails with 401 invalid_swap_auth">
    Pass the swap's `swapAuth` from the create response. If you lost it, recover it with `recoverSwapAuth(id, secretKey)`. Without it, the re-quote cannot be accepted and the swap expires into its refund path.
  </Accordion>

  <Accordion title="A helper returns not-yet">
    Read `reason`. For claims: the lockup lacks your required confirmations, or the deadline is inside the safety margin. For refunds: the timeout has not been reached and the maker did not co-sign.
  </Accordion>

  <Accordion title="Cooperative refund refused">
    `mode: "cooperative"` never falls back. Wait for `timeoutBlockHeight` and refund through the script path, or use `mode: "auto"`.
  </Accordion>

  <Accordion title="ClaimFallbackFailed">
    Both the cooperative and the script-path claim failed. The error carries both causes. Recover through the script path urgently, before the timeout.
  </Accordion>

  <Accordion title="rgb_fee_input_required">
    The HTLC's sats cannot pay the fee and keep the minimum payout. Prepare the spend with `funding: { kind: "callerInputs" }` and add BTC inputs from your wallet.
  </Accordion>

  <Accordion title="Broadcast response lost">
    Rebuild the saved transaction with `BtcLikeTransaction.fromHex` and rebroadcast the same bytes. Check the original txid on your chain backend first. Never sign a new claim or refund to retry.
  </Accordion>
</AccordionGroup>

## Status updates

<AccordionGroup>
  <Accordion title="No updates arrive">
    Make sure `runWsLoop()` is running and you called `subscribeSwap(id)`. A dead socket reports no error, notably after a mobile app is backgrounded: check `isConnected()` and fall back to `swap(id)`.
  </Accordion>

  <Accordion title="The Node process does not exit">
    Call `ws.close()` (TypeScript) or `ws.shutdown()` (Python) when you are done with a status stream.
  </Accordion>
</AccordionGroup>
