## 命名环境模型

`kaleido node` 管理存放在某个基础目录下的**命名 Docker Compose 环境**，该目录默认为：

```text
~/.kaleido
```

每个环境都有自己的 compose 文件和数据卷，因此可以方便地为开发、测试或演示保留彼此独立的本地节点栈。

布局示例：

```text
~/.kaleido/
├── config.json
├── default/
│   ├── docker-compose.yml
│   └── volumes/
│       └── dataldk0/
└── testenv/
    ├── docker-compose.yml
    └── volumes/
        ├── dataldk0/
        └── dataldk1/
```

环境中的每个节点都是一个 `rgb_node_<n>` 服务，各自拥有数据卷。本地运行的只有节点本身：bitcoind、索引器和 RGB 代理都是远程服务。

## 创建环境

```bash
kaleido node create
kaleido node create testenv
```

向导会依次询问：

1. 基础目录
2. 环境名称
3. 节点数量
4. 比特币网络
5. 守护进程与对等节点的起始端口
6. 是否立即启动该环境

## 生命周期命令

| 命令 | 用途 |
|--------|---------|
| `kaleido node list` | 显示所有环境及其节点 URL |
| `kaleido node use <name> [--node N]` | 将当前的 `node-url` 指向某个环境中的某个节点 |
| `kaleido node up <name>` | 启动容器 |
| `kaleido node stop <name>` | 停止容器但不删除数据 |
| `kaleido node down <name>` | 停止并移除容器和网络 |
| `kaleido node ps <name>` | 显示容器状态 |
| `kaleido node logs <name>` | 实时输出日志 |
| `kaleido node clean <name>` | 删除环境的数据卷 |

当只存在一个环境时，`up`、`stop`、`logs` 和 `clean` 等命令可以自动识别它。

## 切换当前活动节点

使用 `kaleido node use` 更新已配置的节点 URL：

```bash
kaleido node use default
kaleido node use testenv --node 2
```

节点 1 使用守护进程端口 3001 和对等端口 9735，节点 2 使用 3002 和 9736，依此类推，起点是创建时选定的基础端口。`kaleido node list` 会用 `●` 标记当前生效的节点。

它是 Docker 管理的环境与所有依赖节点的命令（如 `wallet`、`asset`、`channel` 和 `payment`）之间的桥梁。

## 初始化与解锁 {#initialize-and-unlock}

新环境启动后，对钱包执行一次初始化：

```bash
kaleido node init
```

主要选项：

- `--password` 直接传入钱包密码
- `--mnemonic` 在初始化时用已有助记词恢复钱包

每次重启之后，都需要解锁钱包：

```bash
kaleido node unlock
```

解锁同时决定节点使用哪些比特币服务。交互模式下运行时，它会先让你选择服务配置档 —— signet 默认值、regtest 默认值或自定义 —— 再询问节点如何跟随链。

### 跟链模式

| 模式 | 行为 |
|------|------|
| `--chain-sync block`（默认） | 通过 RPC 从 bitcoind 读取区块 |
| `--chain-sync transaction` | 只依赖索引器跟随链，完全不需要 bitcoind |

使用 `transaction` 时，所有 `--bitcoind-*` 选项都会被忽略：

```bash
kaleido node unlock --chain-sync transaction --indexer-url https://esplora.signet.kaleidoswap.com
```

### 解锁选项

| 选项 | 用途 |
|------|------|
| `--password`、`-p` | 钱包密码，省略时会安全提示输入 |
| `--chain-sync` | 如上，取值 `block` 或 `transaction` |
| `--bitcoind-user`、`--bitcoind-pass` | bitcoind RPC 凭据 |
| `--bitcoind-host`、`--bitcoind-port` | bitcoind RPC 端点 |
| `--indexer-url` | Esplora（`https://…`）或 Electrum（`host:port`） |
| `--proxy-endpoint` | RGB 代理端点 |
| `--announce-alias` | 对外公告的闪电节点别名 |
| `--announce-address` | 用于对等发现的公网地址，可重复传入 |

默认情况下，该命令使用 KaleidoSwap 的 signet 服务。脚本化解锁时请显式传入密码并关闭提示：

```bash
kaleido --agent node unlock --password <password>
```

## 查看状态与上锁

```bash
kaleido node info
kaleido node lock
```

在运行钱包、通道或交换流程之前，用 `info` 确认节点可访问且配置正确。

## 节点交换操作

嵌套的 `swap` 命令组支持节点侧的原子交换与底层交换操作：

```bash
kaleido node swap pubkey
kaleido node swap whitelist --swapstring '30/rgb:abc.../10/rgb:def.../...'
```

## 推荐的本地流程

```bash
kaleido node create devnet
kaleido node up devnet
kaleido node use devnet
kaleido node init
kaleido node unlock
kaleido node info
```

## 运维注意事项

- `clean` 不可撤销，因为它会移除底层数据卷。
- `down` 会移除容器和网络，但保留数据卷。
- `logs` 支持 `--service`，可将输出限定到单个容器。

继续阅读[钱包、资产与支付](/cn/cli/wallet-assets-payments)，了解针对已解锁节点运行的命令。
